# Writing rules

Rules for all prose in this repository: README, docs, commit messages,
code comments. nette's mission is to eliminate AI slop from code. Its own
repository must be slop-free, prose included.

Text must read as if a careful human wrote it. Hard rules:

1. **No em dashes (—) or en dashes (–), ever.** Use a period and a new
   sentence, a comma, parentheses, or a colon. Do not compensate by
   overloading semicolons or colons; restructure the sentence instead.
2. **No contrastive reframes.** Banned structures: "not X, but Y",
   "it's not just X, it's Y", "X is more than Y; it's Z", "The question is
   not X. The question is Y." State the fact directly.
3. **No forced rule of three.** If there are two things, list two. If four,
   list four.
4. **No filler transitions or hedges.** Banned: "It's worth noting",
   "Importantly", "Moreover", "Furthermore", "Additionally" as sentence
   openers. Delete them and state the point.
5. **No AI vocabulary.** Banned as decoration: delve, leverage, harness,
   utilize, seamless, robust, comprehensive, pivotal, cutting-edge,
   groundbreaking, transformative, landscape (metaphorical), ecosystem
   (unless literal), tapestry, realm, journey, empower, unlock. Use the
   plain word: use, full, strong.
6. **No summary conclusions.** Never end with "In conclusion" or a
   restatement. End on the last substantive point.
7. **Vary sentence rhythm.** Mix short sentences with longer ones. Uniform
   length reads as machine output.
8. **Keep the canonical term.** Do not cycle synonyms to avoid repetition.
   Repeating a proper noun is fine.
9. **Specifics over adjectives.** Never "improved performance" when you can
   name the function and the measurement. If a sentence could describe any
   project, delete it.
10. **Self-check before delivering.** Re-read your prose against this list
    and strip every violation.

## Language

All content in this repository (README, docs, code, comments, commit
messages) is written in English.
