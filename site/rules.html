Rules reference

Fifteen rules.
Zero lookup tables.

Rule identifiers are speaking slugs: they name the detected problem, so a finding is understandable without a lookup. A published slug is never renamed. Rules group into families, and a family is what select takes in config.

$ nette explain over-guarded   # the long-form doc for any rule, offline

Three threshold kinds

The distinction is measured, not aesthetic. We profiled five exemplary codebases (httpx, pydantic, fastapi, attrs, curated stdlib): they agree tightly on code shape (median function: 8-13 lines, 2 arguments, near-flat nesting), and they diverge up to 12x on style while all being exemplary.

KindHow the threshold is set
universal A numeric default measured on exemplary codebases, overridable under [tool.nette.thresholds].
calibrated No absolute threshold. The file under judgment is compared to the repository's own profile and fires on deviation from it.
convention A decision the repo makes once and then has to keep. Declared in TOML, never reads the profile: learning from a repo that already drifted would silence the rule where it is needed most.

Measured on a production monorepo: 82% of its data types already lived mixed with behaviour, so a calibrated mixed-module would have gone silent on exactly the debt it exists to catch. That is why convention rules exist.

shape universal

How a function reads at a glance. These defaults ship as numbers because exemplary codebases agree on them.

RuleFires when
function-lengtha function is too long to take in at one glance
branch-densitya function makes too many branching decisions
nesting-depthcode nests too deeply to follow
argument-counta function takes too many required arguments
return-counta function exits from too many places

naming universal calibrated

Scope-aware, not a regex on identifiers. A one-letter name in a two-line comprehension is fine; the same name alive for forty lines is not.

RuleFires when
short-name-long-scopea one-letter name lives too long
naming-driftan identifier breaks the repo's own convention

defensiveness calibrated

Guards are not bad, guards that a repo does not otherwise write are. Both rules read the nearest profile, so a boundary subtree can guard heavily without punishing the CRUD modules next door.

RuleFires when
over-guardeda file guards far more than the rest of the repo
guard-densityone function stacks guards line after line
How a subtree gets its own baseline

annotations calibrated

nette never demands annotations. It demands consistency with what your repo already does, so an untyped codebase stays quiet and a typed one stops leaking.

RuleFires when
under-annotateda file drops the type annotations the repo keeps

structure universal convention

Where code lives and what a module is allowed to hold.

RuleFires when
file-naminga file name breaks snake_case
file-sizea file dwarfs the repo's norm
mixed-moduledata types pile up in a module that also holds logic

duplication convention

The rule an agent loop needs most: an agent asked for a variant of an existing function tends to copy it rather than extend it, and the copy passes every other check.

RuleFires when
duplicated-siblinga function is a near-copy of a sibling function in the same scope

engine

The rules about the run itself. A suppression without a reason, or one that silences nothing, is debt in its own right.

RuleFires when
parse-errora file cannot be judged
bare-allowa suppression carries no reason
unused-allowa suppression silences nothing
