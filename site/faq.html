Questions

The awkward ones, answered.

Including the experiments that came back against the tool. Every number below is reproducible from a script in the repository.

How is this different from ruff?

ruff checks syntax and surface style, faster than anything else, and you should keep it. It has no notion of what your repository decided about type annotations, guard density or file size. nette has no notion of import sorting or unused variables.

They run together. nette's own CI runs both.

Does nette predict which files will have bugs?

No, and we measured it rather than guessed. Five public repositories, 1755 source files, ground truth being the files most touched by correction commits over 24 months.

PredictorPrecision@15AUC
nette, calibrated0.410.83
Counting lines0.610.94
Cyclomatic complexity0.550.90
Random0.080.49

A line count predicts correction churn better than nette does. If that is what you want, count the lines. nette is measuring something else.

Comprehensibility gates usually mean cyclomatic complexity and line length. Why not those?

Because both were tested, by others and by us. A study of 121 metrics against how well developers actually understood code found that none of them correlated, cyclomatic complexity and readability models included.

We ran nette against 119 real Python snippets rated by around 220 developers each. Measured continuously, every dimension nette looks at sat in the noise: longest function +0.02, nesting -0.02, arguments -0.13, branch density -0.05. The one dimension that did correlate is average line length, at -0.26, and ruff already owns it with a universal threshold.

So the gate cannot be a complexity score. What is left, and what nette does, is consistency with the repository the code lands in.

Does the calibrated profile actually catch anything?

Yes, and the effect is uneven enough to be worth stating. Each of five repositories was calibrated on 80% of its files and used to judge the held-out 20% plus the files of the other four. A foreign file is flagged 26% of the time against 12% for a native one, and the gap is carried by the annotation rate rather than by file size.

On repositories with a strict habit it is much wider: poetry flags 42% of foreign files and 0% of its own. On a repository with no habit to enforce it vanishes, because django annotates none of its functions and a rule about annotation has nothing to say.

Calibration sees code looser than its surroundings, never code that is stricter.

Can an agent actually act on a finding?

Twelve flagged files from five public repositories, handed to a model with nothing but the agent output and an instruction to fix without changing behaviour. All twelve reached zero findings, eleven of them in a single turn. No loop oscillated, no new kind of finding appeared, and no public function or parameter was lost.

Published work on models refactoring for readability reports partial convergence and oscillation, and names the missing piece as a principled stopping criterion. This is nette in that role.

When should I not use nette?

When your repository has no consistent style yet. Calibration measures what exists, and on a tree with no convention it records the absence of one.

When you want a risk score. There is none, deliberately, and the research says a single number would be a lie with a decimal point.

When you need security, type or surface-style checks. bandit, mypy and ruff are better at their jobs than any tool that tried to do all four.

When your code is not Python. There is no port, and multi-language tools are shallow in every language.

Is there an MCP server? Does it call an LLM?

No to both, on purpose. nette agent-rules prints the block you paste into AGENTS.md, and --format agent emits deterministic JSON with a run block naming how to rerun and what each exit code means. An MCP server would expose nothing the shell does not, and it only reaches clients that speak MCP. Every agent has a shell.

No LLM runs at check time. A gate that returns a different verdict on the same bytes cannot live in a fix loop and cannot be cached.
